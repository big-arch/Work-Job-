## Карта, статистика и подключения · 23 ноября 2026

[Каталог](http://127.0.0.1:8788/#search) · [Статистика текущего поиска](http://127.0.0.1:8788/#stats) · [Подключение площадок](http://127.0.0.1:8788/#sources).

Главная использует HTML5 Canvas, WebGL и локальную поставку [Three.js r175](https://github.com/mrdoob/three.js/tree/r175) под MIT. Текстура, границы и выбор страны построены по [публичным данным Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/). Без WebGL доступны изображение глобуса и выбор страны из списка. Статистика считается по текущим результатам с учётом выбранного канала и фильтров. Объявления Telegram считаются публикациями.

Карточка группирует опубликованные работодателем поля, исходные разделы, технологии, сведения об оплате и переезде. На досках SmartRecruiters точное описание и поля загружаются при открытии. Источник Хабр Карьера предоставляет краткую карточку по официальному RSS, до 100 последних записей на запрос. Оплата по выборке в статистике означает наличие поля в данных поисковой выдачи.

Для запуска используйте `start-atlas.cmd`. После изменения конфигурации — `start-atlas.cmd restart`. В терминале из папки сайта команды `python configure-source.py hh`, `python configure-source.py superjob` и `python configure-source.py telegram` запрашивают выданный доступ и сохраняют настройки в локальном .env. Включение HH требует отдельно согласовать показ вакансий в публичном каталоге. Для групп Telegram нужен отдельный аккаунт с доступом и Telethon 1.x. Для Работа.ру, LinkedIn и Indeed следующий шаг — согласование партнёрского интерфейса. Инструкции доступны в разделе «Источники». Ключи остаются в серверной конфигурации.

## Поиск вакансий и Telegram

[Поиск BIM](http://127.0.0.1:8788/?q=BIM) открывает живую выдачу. Поиск по запросу на досках Egis, AECOM, Ramboll, SIXT и Endava проходит все публичные страницы по всем городам. Карточка повторно запрашивает полный текст и состояние конкретной вакансии. Для BIM также распознаются запросы «БИМ» и «ТИМ». Кнопка в конце ведёт на оригинальную публикацию. У других подключённых сервисов глубина определяется их открытой лентой. Просроченные снимки и демонстрационные данные исключены из поиска.

Каналы и группы видны отдельно в разделе «Источники». Переключатель Telegram оставляет только объявления из прочитанных сообществ. Каналы читаются по открытым страницам последних 30 дней с постраничной загрузкой. Тексты с признаками резюме, рекламы размещения и явной отметкой закрытия отсеиваются. На открытии карточки сервер запрашивает исходное сообщение. Доступность сообщения подтверждает публикацию, статус найма сообщает работодатель.

Список публичных имён Telegram задаётся в `TELEGRAM_CHANNELS` и `TELEGRAM_GROUPS` файла `.env`. По умолчанию зарегистрированы каналы bimvac, wasa_job, archhunterchannel, archhireglobal, haltura_arhitetura, job_python, remoteit и jobjava. В список групп входят bimwork, bim_tim_work, architect_vacancies, arkhitektory_chat, vacancii_construction, architectsandconstructors и job_in_project. Для групп без веб-ленты доступна история через Telegram API с отдельной авторизованной пользовательской сессией. Установите в выбранном Python `python -m pip install "telethon>=1.36,<2"`, получите API ID/hash на my.telegram.org и создайте StringSession в своём терминале по [инструкции Telethon](https://docs.telethon.dev/en/stable/concepts/sessions.html#string-sessions). Укажите серверные переменные по образцу `.env.example` и перезапустите приложение. Сессия даёт доступ к аккаунту, храните её только на сервере. Чтение ограничено настроенными публичными группами. Без сессии эти группы показаны как ожидающие подключения.

«Работа России» запрашивается через открытый API. Для HH требуется доступ приложения для данного сценария. При отсутствии ключа приложения SuperJob отображается в ожидающих подключения. Для Работа.ру нужен партнёрский интерфейс.

## 1. Суть проекта

«Work & Job» помогает специалисту найти работу в своей стране или за рубежом и понять реальные условия вакансии.

Главная ценность продукта — не карта мира и не количество объявлений, а **честные и проверяемые условия**:

1. Где человек будет работать с первого дня.
2. Какой формат работы указан: офис, гибрид, удалённо.
3. Из каких стран разрешена удалённая работа.
4. Сколько платят, в какой валюте, за какой период и до/после налогов.
5. Можно ли податься из-за рубежа.
6. Есть ли подтверждённая помощь с разрешением на работу или переездом.
7. Когда вакансия была опубликована и проверена.
8. Какой сайт или работодатель является первоисточником.

Если данных нет, интерфейс показывает **«Не указано»**, а не додумывает ответ.

## 2. Исходные документы и анализ

В основу проекта легли две спецификации:

- ранняя концепция с пятью дизайн-направлениями и постепенным запуском функций;
- более новая техническая архитектура с ETL, нормализацией, классификацией условий и контролем конфликтов.

### Главные выводы из анализа

- Сильная сторона продукта — точность данных и различие между местом работы, страной работодателя и удалённой географией.
- Нельзя обещать «100% достоверности»: корректность источника, свежесть и покрытие нужно измерять отдельно.
- Пять визуальных концептов не должны превращаться в пять несвязанных сайтов.
- MVP должен сначала доказать поиск и доверие к карточке, а уже затем добавлять карту, сообщество, чат, монетизацию и сложную инфраструктуру.
- Хеш содержимого нельзя использовать как единственный идентификатор вакансии. Нужны `source + externalId`, канонический URL, компания, локация и история изменений.

## 7. Правила качества данных

### Идентичность

- Основной ключ: `source + externalId`.
- Дополнительно: канонический URL.
- Мягкая дедупликация: компания + нормализованный заголовок + город.
- Для Telegram-снимков URL канала не считается идентификатором отдельной вакансии.

### Неизвестные значения

- `null` в данных;
- «Не указано» в интерфейсе;
- никакого автоматического вывода визы, переезда или налогов;
- `not_specified` не смешивается с «нет».

### Безопасность контента

- HTML источников преобразуется в plain text.
- Нет `dangerouslySetInnerHTML`, `eval` или `new Function`.
- URL ограничиваются HTTP/HTTPS.
- Пользовательские и внешние данные выводятся через обычную интерполяцию React.

### Классификация профиля

- Название роли и конкретные теги важнее общего текста компании.
- Общие категории RSS вроде `Full-Stack Programming` не делают любую профессию технической.
- Убраны ложные совпадения по `development`, `security`, `go` и описанию компании.
- Отдельно исключаются sales, marketing, recruiting, business development, customer support, screenwriting и другие нетехнические роли.

## 9. Анализ n8n workflow `Parsing HH`

Workflow изучен через локальную базу n8n, затем открыт в интерфейсе после входа пользователя.

**Количество узлов:** 23.  
**Executions:** `No executions found` — запуски не подтверждены.

### Цепочка

```text
Manual Trigger
→ HTTP Request к HH API
→ Split Out по items[]
→ Loop Over Items
→ Извлечение полей
→ Добавление резюме
→ LLM: оценка кандидата
→ Tavily: поиск информации о работодателе
→ LLM: оценка работодателя
→ Объединение результатов
→ Airtable + Telegram
```

### Запрос HH

```text
GET https://api.hh.ru/vacancies
    ?text=(BIM менеджер OR BIM координатор)
    &per_page=5
```

Используются:

- `HH-User-Agent`;
- `Authorization: Bearer …`.

Принципиальное отличие от первоначального адаптера Work & Job — OAuth-токен. Это возможная причина различия в 403, но без отдельной проверки с действующей учётной записью причина не доказана.

### Извлекаемые поля

- `employer.name`;
- `name`;
- `salary`;
- `published_at`;
- `apply_alternate_url`;
- `snippet.requirement`.

### Что хорошо в workflow

- Официальный HH API вместо HTML scraping.
- Split Out и пакетная обработка.
- Wait между внешними операциями.
- Запрос JSON у LLM.
- Отдельная оценка кандидата и работодателя.
- Запись результатов в Airtable и уведомление в Telegram.

### Что нужно исправить

1. **Секреты и персональные данные не должны находиться внутри workflow.** Токены перенести в n8n Credentials, а затронутые токены перевыпустить. Резюме передавать через защищённый пользовательский ввод.
2. **Зарплата обрабатывается неполно.** Учитывать `from`, `to`, валюту, период и gross/net.
3. **`JSON.parse` LLM-ответа небезопасен по надёжности.** Нужны JSON Schema, Structured Output и `try/catch`.
4. **Нет pagination, расписания, retry, dedupe, lifecycle и last_verified_at.**
5. **Объединение по индексу массива ненадёжно.** Связывать по `vacancy.id`.
6. **Лишние узлы:** `Merge` и `Inject Resume` не участвуют в основной цепочке.
7. **Название `Create table to Airtable` неверно описывает Telegram-отправку.**
8. **`company_score` нельзя выдавать за объективный факт** без источников, дат, количества отзывов и уровня уверенности.

Workflow не запускался автоматически, поскольку это привело бы к передаче резюме внешним LLM, записи в Airtable и Telegram-отправке.

## 13. Что делать дальше

### Приоритет 1 — проверить HH OAuth

1. Создать/использовать официальное приложение HH.
2. Получить собственный действующий access token.
3. Записать его в `.env` как `HH_ACCESS_TOKEN`.
4. Указать реальный `HH_USER_AGENT`.
5. Проверить только HTTP-запрос HH, без запуска LLM/Airtable/Telegram.
6. Убедиться, что 403 исчезает; если нет — исследовать лимиты и сетевые ограничения.

### Приоритет 2 — подготовить n8n к безопасному тесту

- Перенести секреты в Credentials.
- Удалить персональные данные из общего workflow.
- Отключить выходы в Airtable/Telegram до теста.
- Включить строгую JSON-схему LLM.
- Добавить pagination, retry, dedupe и lifecycle.
- Только затем запускать полный сценарий.

### Приоритет 3 — расширять продукт после проверки спроса

- Полная server-side pagination.
- Планировщик обновлений.
- Постоянная БД вместо файлового MVP-кеша.
- Сохранённые поиски и Telegram Job Alerts.
- Больше официальных ATS boards.
- Три наполненные страницы городов с сопоставимыми расходами.
- Истории специалистов с согласием и источниками.
- Сравнение городов.
- Карта, сообщество и монетизация — только после подтверждения необходимости.

### Метрики пилота

- Поиск → открытие вакансии.
- Вакансия → переход к работодателю.
- Сохранения и возврат через неделю.
- Доля устаревших записей.
- Доля ошибок географического фильтра.
- Доля вакансий с подтверждённой зарплатой и условиями.
- Время ответа и количество доступных источников.

## 14. Принятые ограничения

- Не обещается покрытие буквально всех сайтов вакансий.
- Не создаются внешние аккаунты без учётных данных и прав владельца.
- Leverdemo явно помечается как демо-источник.
- Telegram-снимок не выдаётся за live-обновление.
- Неизвестные Telegram post ID не выдумываются.
- Git-история и новая автоматическая тестовая инфраструктура не создавались; проверка выполнена через реальные HTTP-запросы, сборку, классификационные assertions и браузерные сценарии.
- Production на Node проверен; Docker image ещё требует запуска с работающим Docker daemon.
