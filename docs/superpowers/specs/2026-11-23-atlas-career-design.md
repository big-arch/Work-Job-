# «Атлас карьеры» — реализация MVP

## Намерение

Создать рабочий сайт поиска вакансий для BIM/AEC и IT, который объединяет реальные открытые источники, показывает происхождение и свежесть каждой записи, не выдумывает условия работы и позволяет перейти к отклику у работодателя.

## Выбранный подход

Полнофункциональный локальный fullstack MVP: React + TypeScript + Vite на клиенте, Node/Express API-агрегатор на сервере. Данные загружаются в реальном времени из официальных публичных API и публичных Telegram-страниц с кешированием и ссылками на первоисточники.

Рассмотренные альтернативы:
- Только красивый frontend с демо-данными — отклонено, не отвечает требованию реальных вакансий.
- Сразу production с Supabase, Meilisearch, аккаунтами и планировщиками — отклонено для первого MVP из-за отсутствия учётных данных и лишней инфраструктуры.
- Локальный fullstack с адаптерами — выбран, позволяет проверить реальный сценарий и затем перенести адаптеры в production.

Решение принято автономно в auto permission mode.

## Реализуемые сценарии

- Поиск по должности, технологии, компании и описанию.
- Фильтры по направлению, формату работы, стране/региону и источнику.
- Список вакансий + детальная карточка; на телефоне детальная карточка открывается как нативный modal dialog.
- Сохранённые вакансии в localStorage со снимком данных и переходом к актуальному первоисточнику.
- Раздел городов с тремя пилотными направлениями и реальными результатами фильтрации, без выдуманной стоимости жизни.
- Раздел источников со статусом, количеством записей, ошибками и ограничениями доступа.
- Красивые переходы между разделами, списком и карточкой, stagger-анимации, loading skeleton и мобильный drawer.
- Reduced motion, клавиатурная навигация, live regions, адаптивная вёрстка.

## Источники

Проверены реальными запросами:
- Remotive — 200, официальный публичный API, ссылка и атрибуция обязательны, кеш 6 часов.
- Remote OK — 200, публичный JSON feed, ссылка и атрибуция, кеш 6 часов.
- Arbeitnow — 200, публичный job-board API, ссылка на источник, кеш 1 час.
- Greenhouse — 200 на board `discord`, официальный Job Board API.
- Ashby — 200 на board `linear`, официальный Public Job Posting API.
- Lever — 200 на board `leverdemo`, официальный Postings API; демонстрационный работодатель явно помечается.
- Telegram public channel previews — реальные сообщения доступны у `job_python`, `remoteit`, `jobjava`; низкая частота запросов, ссылка на конкретный пост.
- HH — адаптер официального API реализован, но текущая сеть получает 403; ошибка отображается, остальные источники продолжают работать.

LinkedIn, Indeed, Habr Career и закрытые Telegram-каналы не подделываются и не scrape'ятся в обход ограничений. Для них в реестре указано «нужен официальный доступ».

## Контракт данных

`Vacancy`: стабильный `source:id`, название, компания, описание в plain text, город/страна работы с первого дня при наличии, формат работы, направление, зарплата как опубликованный текст и структурированные значения при наличии, валюта/период/tax basis только из источника, дата публикации и проверки, URL отклика, источник, логотип при наличии, массив тегов, `isDemo` только для Leverdemo.

Неизвестные значения остаются `null` и выводятся как «Не указано». Налоги, релокация и визовая поддержка не угадываются. HTML из источников не вставляется в DOM.

## API и надёжность

- `GET /api/vacancies` — фильтрованный массив, фасеты, статусы источников и `fetchedAt`.
- `GET /api/sources` — реестр и состояние подключений.
- `GET /api/health` — проверка сервера.
- Параллельные запросы с независимыми ошибками, timeout 12 секунд, ограничение размера выдачи и кеш per provider/query.
- Идентичность `source + externalId`; точная дедупликация по canonical URL и дополнительная мягкая только при совпадении компании, заголовка и локации.
- Без глобального fallback с фиктивными вакансиями. Если всё недоступно — честный empty/error state.

## Уточнения после проверки архитектуры

- По умолчанию каталог включает только IT, BIM/AEC, проектирование, дизайн и смежные технические роли. Общие ленты классифицируются по должности, тегам и описанию; непрофильные записи отбрасываются до выдачи.
- Telegram: один пост считается одной карточкой только при явных признаках вакансии. Неизвлечённые поля остаются неизвестными. При прямом чтении канала основная ссылка ведёт на конкретный Telegram-пост. Если сеть блокирует `t.me`, допускается подписанный снимок реальных постов с честной ссылкой на канал; неизвестные post ID не выдумываются.
- Пилотные города: Мюнхен, Дубай и Белград; направления BIM/AEC и IT. Раздел запускает реальный фильтр по городу, без фиктивной аналитики.
- MVP возвращает до 120 лучших совпадений сортировки, интерфейс раскрывает их порциями по 12. Это честно подписывается как актуальная выборка, а не полная выдача всех источников. Полная server-side pagination остаётся следующим этапом.

## Дизайн

Основа Концепта 01: светлый фон, рабочая трёхколоночная область на desktop и одна колонка на mobile. Цвета: тёплый белый, чернильный текст, кобальтовый primary, коралловый акцент. Шрифт Onest с системными fallback. Не смешивать пять стилей и не делать карту главным экраном.

## Ограничения

- Внешние аккаунты не создаются без учётных данных и подтверждения владельца; используются только источники без регистрации.
- Это MVP без централизованной БД, авторизации, синхронизации и фонового production-планировщика.
- Нет обещания «все сайты интернета» или 100% достоверности. Есть расширяемый реестр и честные статусы.

## Критерии готовности

- Production build проходит.
- API возвращает реальные записи минимум из пяти доступных семейств источников, включая Telegram.
- Работают поиск, фильтры, выбор вакансии, внешний отклик, сохранение и удаление, раздел источников.
- При ошибке одного провайдера остальные результаты остаются доступны.
- Проверены desktop 1440×900 и mobile 390×844, reduced motion, отсутствие критических ошибок консоли и горизонтального overflow.
